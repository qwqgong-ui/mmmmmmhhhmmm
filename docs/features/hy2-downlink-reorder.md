# HY2 下行 UDP 乱序恢复（Downlink Reorder）

[返回功能目录](../features.md)

客户端按服务端发出的包序号，恢复同一 HY2 会话内被链路调换的下行数据报，再交给应用。与[上行方向的服务端恢复](https://github.com/qwqgong-ui/Xray-core/blob/SingleUser/docs/features/hy2-udp-reorder.md)对称，面向游戏等会把迟到的旧包计为丢包的 UDP 应用。

## 为什么需要

QUIC 给自己的每个包编号，但 RFC 9221 的 DATAGRAM 帧按到达顺序交付，quic-go 的接收队列是纯切片，**不还原顺序**。所以链路上的乱序原样穿透到内层：隧道自己毫发无伤（丢包判定阈值是 3 个包），承载的 UDP 却直接看到相邻包互换。TCP 经 HY2 不受影响，因为它走的是 STREAM 帧，顺序在隧道里就被重组了。

2026-09-20 实测本机经 IPv6 连东京与洛杉矶两台服务器：

- 服务端开启 UDP GSO 时，每 1500–2000 个数据报有 87–294 次乱序；间隔 1 ms 发送时六次测量全为 0。
- 倒置距离几乎全是 1（一次详细抓取为 `{1: 136, 2: 2}`），互换发生在同一批背靠背的包之间。
- **完全不用 GSO、只把包背靠背发出**同样复现（东京 171 次、洛杉矶 76 次），所以成因是包间距而非 GSO；阈值约在 100 µs。
- 同样的代码与 GSO，**东京与洛杉矶互发 1500/1500 零丢包零乱序**，两个方向都是。
- 在客户端网卡抓包得到 173 次倒置、socket 交付 179 次，两者一致，说明包到达本机之前就已经乱了；到达间隔被整成均匀的 31 µs。

即乱序来自客户端侧的接入网络，代码无法阻止，只能恢复。

## 状态与边界

- 按序到达的数据报立即交付，不增加延迟。
- 序号出现不超过 32 的缺口时，先到的数据报最多暂存 2 ms，缺口补上即按序交付；超时则放弃缺口按序放行，之后迟到的包直接交付。
- 缺口超过 32 视为丢包过多或计数重置，立即交付并重新确认连续性；单会话最多暂存 64 个数据报。
- 会话要先连续出现 8 个递增序号才会暂存任何数据报。包序号恒为 0 或随机取值的服务端（未升级的 Xray、官方实现）永远达不到，照常直通。
- sing-quic 以 65535 取模计数、不发送 0xFFFF，跨越回卷不算缺口。
- 重排在分片重组之前，同一序号的分片按到达顺序保持在一起。
- 会话关闭时停止定时器并释放仍在暂存的数据报。

需要配套的终端：Xray 服务端要给下行数据报按会话递增编号，否则客户端没有排序依据、照常直通。
