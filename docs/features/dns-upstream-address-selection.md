# DNS 上游地址竞争与胜出连接复用

[返回功能目录](../features.md) · [配置示例](../config.yaml)

更新于 2026-10-01，以当前 `dev` 源码为准。

## 地址选择

DNS 上游填写域名时，首次使用会并发解析 A、AAAA，并对返回的各个 IPv4、IPv6 地址发起真实 DNS 查询。某一批地址先解析完成就先开始查询，不等待另一地址族；IPv6 被禁用时只使用 IPv4。

选择最先返回有效 DNS 响应的地址，不再强制优先 IPv6。比较的是完整查询完成时间，包含首次连接及握手成本、网络传输和服务器处理时间；不是 ICMP ping 的延迟，也不是复用连接后单独测得的稳态查询延迟。

该逻辑覆盖 UDP、TCP、DoT、DoQ，以及 DoH 的 HTTP/1.1、HTTP/2、HTTP/3 传输。UDP 以实际 DNS 响应为依据，不以创建 socket 的速度判断。连接固定到候选 IP，原始域名仍用于 TLS 证书验证、SNI、HTTP 请求和域名规则匹配。

选择状态属于每个上游传输实例。多个已配置的 DNS 上游之间仍遵循原有策略与并发查询逻辑；本功能选择的是同一个上游域名解析出的地址。直接填写 IP 地址的上游不参与域名地址竞争。

## 复用与失败重选

- 选定后，后续查询直接使用胜出地址，不重新解析上游域名或重复竞争，也没有定时重选。
- 上游连接或查询失败、空响应、上游 Fake-IP 响应、SERVFAIL、REFUSED 会触发重新解析和竞争。有效的 NXDOMAIN 响应不触发重选。
- 调用方取消或其上下文超时不会清除胜出地址。重新选择时，同一个实例只允许一个调用方执行竞争，等待者随后复用选出的地址。
- 落败查询取消，其连接在占用释放后关闭，不保留为长期备用池。已建立的 DoQ 连接通过 QUIC 正常关闭机制通知对端，停止保活。
- `ResetConnection` 会重置现有传输连接，但保留胜出地址；之后仍先向该地址重连，失败才重选。

## DoQ 连接与流

胜出地址的 QUIC 长连接可供多个查询复用，每个查询使用独立双向流，允许并发执行。保活用于维护胜出连接；落败连接关闭后不再发保活包。

当前没有四连接备用池、预开四流或按业务空闲时间回收的功能。DoQ 尚未设置 TLS `ClientSessionCache`，没有启用 TLS 会话恢复或 0-RTT 查询；QUIC `TokenStore` 缓存地址验证令牌，不等于 TLS 会话缓存。这些能力不能由“支持 QUIC”或“允许会话票据”推定为已经启用。

## 实现与验证

- `dns/address_race.go`：逐地址查询、胜出地址缓存、错误重选及落败连接回收。
- `tunnel/dns_dialer.go`：候选 IP 固定与域名信息保留，取消强制 IPv6 优先。
- `component/dialer/dialer.go`、`component/dialer/options.go`：DNS TCP 地址并发连接选项。
- `dns/doq.go`、`dns/doh.go`、`dns/dot.go`：连接复用及取消处理。
- `dns/address_race_test.go`：多地址竞争、取消与连接关闭、胜出复用、失败重选，以及本地 UDP、DoQ、HTTP/3 传输测试。
- `component/dialer/concurrent_tcp_test.go`：全部 TCP 地址竞争及落败拨号取消测试。

测试和单次外部测速只代表对应运行时环境。首次握手最快的地址与长连接复用后最快的地址可能不同，不能把一次测速结果作为永久的地址优先级。
